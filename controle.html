02 — Anomalies

Cinq anomalies, cinq corrections

Pour chaque anomalie : ce que l'on constate, la cause trouvée dans le code et la correction apportée. Les numéros de ligne correspondent au projet fourni.

Fonctionnement
2 anomalies
Anomalie 01
Routage LivreController.php ↗

ConstatAvec le compte documentaliste, on ne peut pas ajouter de livre : on arrive sur une erreur 404 (dans var/log/dev.log : « App\Entity\Livre object not found »).

CauseLigne 27, la route livre_show (/livres/{id}) est déclarée avant livre_new (/livres/nouveau) et {id} accepte n'importe quel texte, donc Symfony prend « nouveau » pour l'id d'un livre. On le voit avec debug:router.

CorrectionAjout de requirements: ['id' => '\d+'] sur livre_show pour que {id} n'accepte que des chiffres.

Anomalie 03
Doctrine LivreController.php ↗

ConstatUne fois la page d'ajout réparée, le message « Le livre a été ajouté au catalogue » s'affiche mais le livre n'apparaît pas dans le catalogue.

CauseLigne 43, il y a $em->persist($livre) mais pas de $em->flush(), donc rien n'est enregistré en base.

CorrectionAjout de $em->flush() après le persist().

Anomalie 02
Faille XSS show.html.twig ↗

ConstatQuel que soit le compte, en ouvrant le septième livre (« Voyage au centre de la Terre »), un pop-up oblige à cliquer sur OK avant d'afficher la page. Même chose après une modification.

CauseLigne 15, la description est affichée avec |raw : Twig n'échappe pas le HTML et le script alert(1) présent dans la description est exécuté par le navigateur. Un script malveillant pourrait voler la session des utilisateurs.

CorrectionSuppression du |raw : le script s'affiche maintenant comme du texte.

Anomalie 04
Injection DQL LivreRepository.php ↗

ConstatUne recherche contenant une apostrophe (par exemple « l' ») provoque une erreur 500.

CauseLigne 32, le texte de la recherche est collé directement dans la requête DQL, l'utilisateur peut donc modifier la requête.

CorrectionUtilisation d'un paramètre : ->andWhere('l.titre LIKE :q')->setParameter('q', '%' . $q . '%').

Anomalie 05
Contrôle d'accès security.yaml ↗

ConstatAvec le compte élève, on peut aller sur /livres/1/modifier et modifier un livre, alors que c'est réservé aux documentalistes.

CauseLignes 32-33, la règle ^/livres (ROLE_USER) est placée avant celle des documentalistes. Symfony applique seulement la première règle qui correspond, celle des documentalistes n'est donc jamais utilisée.

CorrectionLa règle des documentalistes est placée avant ^/livres. L'élève obtient maintenant une erreur 403 sur l'ajout, la modification et la suppression.
